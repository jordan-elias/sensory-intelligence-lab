a deep dive: how neural networks work

This is a long essay, written for people who are curious about what neural networks actually are and are willing to follow some arithmetic. It does not assume you know any mathematics beyond multiplication and addition, but it does not avoid the mathematics either, because the mathematics is the explanation. Everything described here is happening, live, in the network above.

1. What a neural network is

A neural network is a function: something that takes in a list of numbers and produces another list of numbers. What makes it special is how the function is built and how it is found. It is built from many very simple units, each doing a tiny calculation, wired together in layers. And it is not written by anyone: its behaviour is set by thousands to billions of adjustable numbers, called parameters, and those numbers are found by showing the network examples and nudging them, a little at a time, in whatever direction makes its mistakes smaller. This process is called training.

That is the whole idea. An image classifier is a function from the brightness of every pixel to a list of probabilities for "cat", "dog", "car". A speech recogniser is a function from sound to text. A language model is a function from the words so far to a probability for each possible next word. The network above is a function from six wandering numbers to eight outputs, and it is being trained to make those outputs spell out a chord. Same machinery, much smaller.

The network here has 6 inputs, then two hidden layers (10 and 8 neurons by default), then 8 outputs. With the default shape it has 230 adjustable numbers: 60 + 80 + 64 = 204 weights, plus 10 + 8 + 8 = 26 biases (both terms are explained below). The live count is shown under the picture, and it changes when you change the size of the layers.

2. Where the idea comes from

In 1943 Warren McCulloch and Walter Pitts proposed a simplified mathematical model of a neuron: a unit that adds up its inputs and "fires" if the total passes a threshold. In 1958 Frank Rosenblatt built the perceptron, a machine that used a unit like this and could learn to classify simple patterns by adjusting its weights. It attracted enormous attention, and enormous promises.

In 1969 Marvin Minsky and Seymour Papert published Perceptrons, which showed, rigorously, that a single layer of such units cannot compute some simple functions, the best known being exclusive or (XOR: output 1 if exactly one of two inputs is 1). Networks with a hidden layer can, but at the time there was no good way to train them, and interest and funding in the field fell away for years.

The method that solved this was backpropagation: an efficient way of working out how every weight in a many-layered network contributed to an error. Its mathematical ingredients had been discovered more than once by different people (reverse-mode automatic differentiation in the 1960s and 1970s, and Paul Werbos's 1974 thesis applying it to networks), and the 1986 paper by David Rumelhart, Geoffrey Hinton and Ronald Williams showed convincingly that it made networks learn useful internal representations. In 1989 Yann LeCun and colleagues used a convolutional network trained by backpropagation to read handwritten postcode digits. In 1997 Sepp Hochreiter and Jürgen Schmidhuber introduced the LSTM, a unit for learning from sequences.

For about two decades after that, other machine-learning methods were often better in practice. The turn came in 2012, when a deep convolutional network, AlexNet (Alex Krizhevsky, Ilya Sutskever and Geoffrey Hinton), won an image-recognition competition by a wide margin. Three things had come together: much more labelled data, graphics processors that could do the arithmetic fast, and a set of practical improvements to training that made deep networks work. Since then the field has moved quickly: generative adversarial networks (2014), networks that beat human champions at Go (2016), and the transformer architecture (Vaswani and colleagues, 2017), which underlies most current large language models.

3. The neuron: a weighted vote

A neuron receives some numbers. Each incoming connection has a weight, which says how much that input counts. The neuron multiplies each input by its weight and adds up the results. It then adds a bias, a number of its own that shifts the total up or down whatever the inputs are. The result is called the pre-activation and is usually written z. Finally z is passed through an activation function f, which produces the neuron's output a.

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b a = f(z)

It is a vote in which some voters count more than others (their weights), some count against (negative weights), and the neuron has a built-in leaning (its bias). If you select any neuron in the picture above, the Neuron tab shows precisely this: every input, the weight applied to it, the product, the total and the output.

A worked example. A neuron has inputs 0.5 and -1, weights 0.8 and 0.3, and bias 0.1. Then z = 0.5×0.8 + (-1)×0.3 + 0.1 = 0.4 − 0.3 + 0.1 = 0.2. With tanh as the activation function, a = tanh(0.2) ≈ 0.197.

A word on biology. The name "neural network" and the diagrams of connected circles come from an analogy with the brain, and the analogy was a real source of the idea. But the analogy is loose. A real neuron is an elaborate cell with many kinds of chemistry and timing, and brains learn by mechanisms that are not backpropagation. Artificial neurons are best thought of as a convenient mathematical building block, inspired by biology but not a model of it.

4. Layers, and the matrix view

Neurons are arranged in layers, and every neuron in a layer takes input from every neuron in the layer before. If you collect all the weights going into a layer into a table (a matrix W, with one row for each neuron in the layer and one column for each neuron in the layer before it) and all the biases into a list b, then the whole layer's calculation is one line:

a_next = f( W · a_previous + b )

The Weights tab above shows exactly these tables, one for each pair of layers. A network is this line repeated: the output of one layer becomes the input of the next, until the last layer produces the answer. This pass from input to output is the forward pass. It is the reason graphics processors are so good at neural networks: matrix multiplication is what they were built for.

The first layer is the input layer, which just holds the data. The last is the output layer, whose values are the answer. Everything in between is hidden, a word that only means "neither input nor output". "Deep" learning means many hidden layers.

Parameter counts: a layer going from m neurons to n neurons has m × n weights and n biases. Doubling the width of a layer therefore roughly quadruples its weights. Large systems have billions of parameters; this one has a few hundred.

5. Why the activation function matters

Suppose there were no activation function, so each neuron simply output its weighted sum. Then two layers in a row would compute W₂(W₁x + b₁) + b₂, which can be rewritten as (W₂W₁)x + (W₂b₁ + b₂): that is, a single layer with different weights. A hundred layers would collapse into one. Without a nonlinearity in between, depth adds no power, and a linear function can only ever draw straight boundaries through the data. XOR cannot be separated by a straight line, which is exactly the limitation Minsky and Papert pointed out.

The activation function bends the line. Once every layer applies a nonlinear function, stacking layers lets the network compose simple bends into complicated shapes. There is a famous mathematical result, the universal approximation theorem (George Cybenko, 1989; Kurt Hornik, 1991), which says that a network with just one hidden layer and enough neurons can approximate any continuous function on a bounded region as closely as you like. It is a reassuring fact, and it is easy to misread: it says such a network exists, not that training will find it, nor how many neurons would be needed. In practice, depth tends to be far more efficient than width.

Different functions have different characters. This page offers four, which you can choose for each hidden layer and compare in the reference section above. tanh and softsign squash every input into -1 to +1, and flatten out for large inputs (saturation). Leaky ReLU passes positive values unchanged and nearly blocks negative ones; the plain version, the rectified linear unit, became the default choice in large networks because it does not saturate on the positive side and is cheap to compute. Sine is periodic and unusual, and makes a neuron respond in bands. The output layer here always uses tanh because the targets are between -1 and +1.

6. How a network learns

Learning needs a way of saying how wrong the network is. That is the loss function: a single number, computed from the network's outputs and the correct answers, which is large when the network is wrong and zero when it is perfect. This network uses the mean squared error: for each output, take the difference between what the network said and what it should have said, square it, and average. The number labelled "Error (loss)" under the picture is that.

loss = average of (output − target)²

Other problems use other losses. For classification, cross-entropy is standard: it penalises a network heavily for being confidently wrong. The choice of loss is a choice about what counts as a mistake, and it matters.

Now imagine all the parameters of the network as coordinates, so that the network at any moment is a point in a space with hundreds, or billions, of dimensions. The loss is a height at each point: a landscape. Training is a walk downhill on this landscape. At the current point you work out which way is steepest, and take a small step that way. The steepness and direction at a point are given by the gradient (a list containing the slope of the loss with respect to each parameter), and the method is gradient descent. The size of each step is the learning rate, which you can set in the Network tab.

w ← w − η × (slope of the loss with respect to w)

The hard part was never the stepping; it was finding the slope for every one of millions of parameters efficiently. That is what backpropagation does.

7. Backpropagation, step by step

The slope of the loss with respect to a weight can be found with the chain rule from calculus: if A affects B and B affects the loss, then the effect of A on the loss is the effect of A on B times the effect of B on the loss. The network is a chain of such steps, so the effect of any weight on the loss is a product of local effects along the path from that weight to the output.

Backpropagation arranges the arithmetic so that it is done once, working from the output backward. For each neuron, define δ (delta) as the slope of the loss with respect to that neuron's pre-activation z. For an output neuron with target t:

δ = (2 / n) × (output − target) × f′(z)

Here n is the number of outputs and f′ is the slope of the activation function at z: how sensitive the neuron is, right now, to a change in its input sum. For a hidden neuron, the error is whatever it contributed to the deltas of the neurons it feeds, weighted by the connections:

δ(hidden) = f′(z) × Σ ( weight to next neuron × δ(next neuron) )

That is the "back-propagation" of error: each layer's deltas are computed from the next layer's. Once a neuron has its δ, the update for every weight going into it is the same simple rule:

Δw = −η × δ × (the input that came along that weight) Δb = −η × δ

Pick any neuron and look at its table in the Neuron tab: the "Its output" column is the input to each weight, and those are exactly the numbers that multiply δ in the update.

Worked example, continued. Take the neuron from earlier (inputs 0.5 and -1, weights 0.8 and 0.3, bias 0.1, output 0.197) and suppose it should have output 0.9. With one output, δ = 2 × (0.197 − 0.9) × (1 − 0.197²) ≈ -1.35, where the last bracket is the slope of tanh at that point. With η = 0.05:

  • weight 1: 0.8 − 0.05 × (-1.35) × 0.5 ≈ 0.834
  • weight 2: 0.3 − 0.05 × (-1.35) × (-1) ≈ 0.232 (it goes down, because its input was negative)
  • bias: 0.1 − 0.05 × (-1.35) ≈ 0.168

Running the neuron again gives tanh(0.5×0.834 − 0.232 + 0.168) = tanh(0.352) ≈ 0.338: closer to 0.9. This is repeated many times, and the page does it about twenty times a second across all its parameters at once. The numbers in this example are checked by an automatic test against the code that runs this page.

In 1986 this was a breakthrough; today it is automated. Machine-learning software records the calculations of the forward pass and computes all the gradients for you (automatic differentiation), so nobody writes backpropagation by hand for each new architecture.

8. Making learning work in practice

Learning rate. Too small and learning is painfully slow; too large and each step overshoots the valley and the loss bounces or blows up. You can see both here: set the learning rate to its lowest, and the network trails the changing chords; set it high and it follows quickly but with overshoot and roughness.

Stochastic and mini-batch gradient descent. Real training data has millions of examples. Computing the exact gradient over all of them for every step is wasteful, so training uses small random batches. The gradient from a batch is a noisy estimate of the true one, but it is far cheaper, and the noise is even helpful. This page takes the extreme form, one example at a time, because its "dataset" is a single moving input.

Better optimisers. Plain gradient descent has many refinements. Momentum keeps some of the previous step's direction, which smooths the path; Adam (Diederik Kingma and Jimmy Ba, 2014) adapts the step size of each parameter individually, and is among the most widely used methods.

Initialisation. You cannot start with all weights equal to zero. If two neurons in a layer start identical they receive identical updates for ever and stay identical, so the layer is wasted. Weights are started at small random values, and their scale is chosen so that signals neither shrink nor grow as they pass through layers. This page uses Xavier (Glorot) initialisation, from a 2010 paper by Xavier Glorot and Yoshua Bengio, which draws weights with a spread of √(2 / (inputs + outputs)). For ReLU units a related scheme (He initialisation) is used.

Normalisation, regularisation and data. Large networks add many further techniques, such as normalising the numbers in each layer, and using weight decay (a small pull that keeps weights from growing), dropout (randomly silencing neurons during training; Nitish Srivastava and colleagues, 2014) and data augmentation (training on altered copies of the data). The common purpose is to help the network generalise, which is the next topic.

9. What goes wrong

Overfitting. A network with enough parameters can memorise its training examples, including their noise, and then perform badly on new ones. What you want is generalisation: doing well on examples it has never seen. This is why data is split into a training set (used to learn), a validation set (used to tune choices) and a test set (touched only at the end to measure real performance). A falling training loss alone tells you very little.

Vanishing and exploding gradients. In a deep network the gradient for early layers is a long product of numbers from later layers. If those numbers are mostly smaller than one the product shrinks toward zero and early layers barely learn; if mostly larger than one it explodes. Saturating activation functions make the first problem worse: where a tanh neuron is saturated, its slope f′(z) is close to zero, and almost no learning signal passes through it. Much of the progress of the last decade is a catalogue of fixes for this: ReLU-style activations, careful initialisation, normalisation layers and residual connections (see below).

Dead neurons. A plain ReLU neuron whose input is always negative outputs zero and has zero slope, so it can never recover. The "leaky" version used here keeps a small slope on the negative side for that reason.

Local minima, plateaus and saddle points. The loss landscape is not a simple bowl. In very high dimensions, however, pure local minima turn out to be rarer than saddle points (flat regions that slope down in some directions), and the practical difficulty is more often slow progress along plateaus than being trapped.

Optimising the wrong thing. A network minimises the loss you give it, not what you meant. If the loss rewards the wrong thing, or the data is unrepresentative, the network will faithfully learn that. The most important problems with deployed networks are usually problems of data and objectives, not of arithmetic.

10. What the hidden layers become

Nobody tells a hidden neuron what to detect. Training pushes its weights toward whatever combination of its inputs helps reduce the loss, so its meaning emerges. In image networks, researchers who visualised what neurons respond to found a rough hierarchy: neurons in early layers respond to edges and colour contrasts, middle layers to textures and parts, later layers to whole objects. The network builds up its own description of the data, layer by layer. These descriptions are called representations, and the ability to learn good ones, rather than having a human design them by hand, is the real strength of the approach.

A particularly useful kind of representation is an embedding: a list of numbers that places each word, image or song at a point in a space where similar things are close together. Word embeddings learned from large amounts of text famously capture some relationships as directions in the space (the vector from "man" to "woman" is roughly similar to that from "king" to "queen"), though such examples are approximate and are easier to pick out than to rely on.

Interpreting what a trained network is doing is a hard and active research field. For a large network it is generally not possible to say, in a sentence, why it produced a particular output. On this page, you can do a small version of the investigation yourself: select a neuron in the second hidden layer, silence it, and listen to what changes. That is a miniature of an ablation experiment, a standard technique in interpretability research.

11. Architectures: networks of many shapes

The network on this page is a multilayer perceptron (MLP), or fully connected network. It is the plainest design. Most of the progress in practical systems has come from architectures that build in assumptions about the data:

  • Convolutional networks are designed for images and other grid-like data. A small filter of shared weights slides across the image, so the same pattern is detected wherever it appears. Reusing weights makes them far more efficient than connecting every pixel to every neuron.
  • Recurrent networks process sequences one step at a time, feeding some of their output back as input to the next step, which gives them a form of memory. LSTM and GRU units add learned gates that control what to remember and forget.
  • Transformers (2017) replace recurrence with attention: for each position in a sequence, the network computes how relevant every other position is, and takes a weighted average of what it finds. This can be computed in parallel across the whole sequence, which suits modern hardware and scales well. Transformers are the basis of most current language models and are also used for images, audio and more.
  • Autoencoders are trained to squeeze data through a narrow middle layer and reconstruct it, so the middle layer becomes a compact representation.
  • Generative adversarial networks (Ian Goodfellow and colleagues, 2014) pit a generator, which makes fake examples, against a discriminator, which tries to tell fakes from real ones, so that each improves the other. Diffusion models learn to reverse a process of gradually adding noise, and generate images and audio by starting from noise and removing it step by step.
  • Reinforcement learning uses a network to choose actions, and trains it from rewards rather than correct answers. It was central to the systems that mastered Go and many video games.

Residual connections, which add a layer's input directly to its output, deserve a note: they let information and gradients bypass layers, and are what made networks of hundreds of layers trainable. The reference section above lists these and other units.

12. How large language models fit in

A large language model is a transformer network with billions of parameters trained on a very large amount of text. The basic training task is next-token prediction: given a stretch of text, predict what comes next. A token is a piece of a word. The loss is the cross-entropy between the network's predicted probabilities and the word that actually followed. To predict well across enormous quantities of varied text, the network has to build internal representations of grammar, facts, styles and a great deal more, which is why such a simple objective yields general abilities.

The raw trained model is then usually refined, often with fine-tuning on examples of the desired behaviour and with feedback from human raters, to make it follow instructions and avoid harmful output. When a model generates text, it does something very like the note choice on this page: it computes a probability for each possible next token, and one is drawn, with a setting (the temperature) controlling how adventurous the draw is. The Adventure slider is the same idea.

The key differences from this page are scale, the architecture, and above all the data. Understanding the mechanism does not make the behaviour of a large model predictable, and it is important to remember that such a model produces plausible text, which is not the same as true text.

13. What they are used for

  • Images and video: recognising objects and faces, reading handwriting and documents, medical imaging (for example, helping flag suspicious regions in scans for a clinician to review), generating and editing pictures.
  • Speech and language: speech recognition and synthesis, translation, summarisation, search, and conversational systems.
  • Science: predicting the three-dimensional structure of proteins from their sequence (AlphaFold), modelling materials and weather, and finding patterns in large experimental data sets.
  • Recommendation and ranking: which video, product or song to show next; this is one of the largest commercial uses.
  • Control and games: robotics, game-playing, and optimising complex systems.
  • Audio and music: separating a mix into instruments, transcribing music, noise reduction in phones and hearing aids, compressing audio, and generating sound and music. For a field built on sound, they are now everywhere.

In health and mental-health settings the potential is real and so are the risks. Networks can pick up subtle patterns in speech, text or physiological signals, but a pattern is not a diagnosis, models can perform much worse on groups that were poorly represented in their training data, and training such models typically requires gathering large amounts of very sensitive personal information. Those are among the reasons this Lab keeps your data encrypted on your device and calculates its insights there.

14. Limits, risks and open questions

  • Opacity. A trained network is a large pile of numbers. It is difficult to explain individual decisions, which matters where decisions affect people.
  • Bias. A network learns the patterns in its data, including unfair ones. It can reproduce and amplify them while looking objective.
  • Brittleness. Networks can fail on inputs unlike those they were trained on, and can be fooled by adversarial examples: tiny, carefully chosen changes to an input that humans cannot perceive but that change the output completely.
  • Confident error. Generative systems can produce fluent output that is false. Fluency is not evidence.
  • Privacy. Models can sometimes reveal parts of their training data, and building them concentrates personal data. Approaches such as training or running models on the user's own device exist partly for this reason.
  • Cost and power. Training the largest models takes a great deal of computation and energy.
  • Open questions. Why large networks generalise as well as they do despite having so many parameters, how to interpret them reliably, and how to align their behaviour with human intentions are all active areas of research, without settled answers.

15. What this page is and is not

Real: the network, its loss, its learning, and every number going through it. The neuron tables, the weight tables and the formulas you see are read directly from the running network, and the example calculations in this essay are checked against its code.

Chosen: every mapping from numbers to sound. Making the first hidden layer a drone, the second a shimmer and the output a melody is a composer's decision, and other mappings would make the same network sound entirely different. This is sonification: a way of making the shape of a computation audible. It is not the voice of a mind. The network has no understanding of music, or of anything: it adjusts a few hundred numbers to match a pattern of eight values.

Also simplified: the network learns online, from one constantly changing example, rather than from a large data set in batches; it has no validation data and so cannot overfit in the usual sense; and its goal keeps moving by design, so it never converges. These choices are what make it musical.

16. Experiments to try here

  1. Ablation. In the Neuron tab, silence a neuron in hidden layer 2 and listen. Then silence a different one. Do some matter more than others? Does the network adapt over the next minute by relying on the others?
  2. Capacity. In the Network tab set both hidden layers to 2 neurons. Can it still track the chord? Now set them to the maximum. What does extra capacity buy, and what does it cost in the time taken to learn?
  3. Nonlinearity. Change hidden layer 1 to leaky ReLU, then sine. Which changes the sound of the drone most? Which settles to a lower loss?
  4. Teaching. Select the output neuron for the 1st scale degree and set "Teach it" to always on. Then to always off. Listen to the melody follow.
  5. Freezing. Freeze every neuron in hidden layer 2 (one by one), and watch the loss when the next chord change arrives. What can a network do if only part of it is allowed to learn?
  6. Cutting connections. In the Weights tab select the largest weights in a layer and cut them. How quickly does the network repair itself?
  7. Learning rate. Set it to the minimum, then the maximum. Describe how each sounds, and how the loss trace in the picture looks.
  8. Heat and pace. Turn both up and wait for an episode. Then hold the goal still and watch the loss trace flatten.

17. Glossary

Activation (of a neuron)
The neuron's output for the current input.
Activation function
The nonlinear function applied to a neuron's weighted sum.
Backpropagation
An efficient way to compute the gradient of the loss with respect to every weight, by working backward from the output.
Batch / mini-batch
A group of training examples used together for one update.
Bias
A neuron's own constant added to its weighted sum.
Cross-entropy
A loss for probabilities that penalises confident wrong answers heavily.
Embedding
A learned list of numbers representing an item, placed so that similar items are near each other.
Epoch
One full pass through the training data. (This page uses "episode" for a change of goal.)
Forward pass
Computing the output from the input, layer by layer.
Generalisation
Performing well on examples not seen in training.
Gradient
The list of slopes of the loss with respect to each parameter.
Gradient descent
Repeatedly stepping parameters against the gradient to reduce the loss.
Hidden layer
A layer that is neither input nor output.
Hyperparameter
A setting chosen by the designer, such as the learning rate or layer sizes, rather than learned.
Learning rate
The size of each parameter update.
Loss
A number measuring how wrong the network currently is.
Overfitting
Fitting the training data, noise included, at the cost of performance on new data.
Parameter
Any number the network learns: the weights and biases.
Regularisation
Any technique that discourages overfitting.
Representation
The internal description of the data that a layer builds.
Saturation
A neuron's output sitting on the flat part of its activation function, where its slope, and so its learning, is near zero.
Softmax
A function turning a list of numbers into probabilities that sum to one.
Sonification
Turning data into sound.
Weight
A learned number scaling one connection.
